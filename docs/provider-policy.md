# Provider policy

**Binding project decision, 2026-11-04: no paid API, ever.** Not a paid API, not a pay-as-you-go
service, not a billable fallback, not a free trial that can become paid, not a free tier whose
limits, terms or billing exposure are unclear. A provider is approved only when its pricing,
terms, licensing, commercial-use rules, rate limits, caching rules and polling permissions are
clear for Voyagr's actual use and cannot automatically create a charge. This overrides anything
older in this repository that says otherwise - an env default, a comment, a prior decision, or an
agent's assumption.

This document exists because that policy was found **not enforced in code** by the 2026-11-04
audit: `docs/provider-evaluation.md` already said Duffel was ruled out, but a real production
build's own startup log showed `FLIGHT_PROVIDER=duffel` active. The fix for that is recorded
below, under Flights. This file is the one place the actual, current, code-enforced status of
every provider is tracked - keep it in sync with `src/providers/registry.ts` and
`src/lib/env.ts` whenever either changes.

## Legacy flight providers (off by default)

`FLIGHT_PROVIDER` now defaults to `kiwi-mcp`. `aviasales`, `liteapi` and `live` stay in the tree but
a production build refuses them unless `ALLOW_LEGACY_FLIGHT_PROVIDERS=true` (`parseEnv` in
`src/lib/env.ts` and the registry both enforce it). Outside production they are still selectable.
The Aviasales and Google Flights rows in the table keep their earlier terms notes; those sources are
not used unless someone turns them on on purpose. The earlier owner decision (Aviasales for flights)
is overridden for the default by this branch; see `docs/autonomous-run/DECISIONS.md`.

## What "fail closed" means here, concretely

- `FLIGHT_PROVIDER`, `HOTEL_PROVIDER`, `WEATHER_PROVIDER`, `TRANSFER_PROVIDER`, `PLACES_PROVIDER`
  each resolve through `src/providers/registry.ts`. Any value that is not an approved, implemented
  adapter throws `AppError('CONFIGURATION_ERROR', ...)` **before building anything and before any
  network call**, naming which setting was the problem - never a silent fallback to a mock
  wearing a "live" label, and never a silent fallback to a different, unapproved live vendor.
- A provider that needs a credential (Aviasales) refuses to build at all without one, at startup,
  rather than failing on the first search.
- No user-controlled input (a cookie, a query parameter, a request header) can select a provider.
  `src/providers/data-source.ts`'s own switch only ever chooses between `'api'` (whatever
  configuration already named) and `'mock'` - it cannot name a vendor, and `parseDataSource`
  refuses anything else, including `'duffel'` itself (tested in
  `src/providers/registry.test.ts`).
- `src/providers/registry.test.ts` proves, with a `fetch` spy, that none of the above makes a
  single outbound call: not for Duffel (impossible to select), not for an unknown provider name,
  not for a provider missing its required credential.

## Changing this policy

A provider's status changes only by editing this table, with its evidence column filled in from a
source you actually checked (its real pricing page, its real terms of service, a direct answer from
the vendor) - never from a free-tier badge alone, and never from an assumption that a sandbox key is
risk-free. Update `src/lib/env.ts` and `src/providers/registry.ts` to match in the same change: this
document and the code must never disagree about what the code can actually reach.

## Decision 2026-11-17: hotel booking

Owner decision: Voyagr does not take payments or sell bookings. Hotel prices and photos come from LiteAPI (Nuitee); the person books and pays on the hotel provider or its own page. LiteAPI's standard hotel booking requires the seller to collect payment (its SDK, Stripe Elements or a credit line), so it is not used for booking. Its hosted booking site (Whitelabel) is undocumented on who takes payment; not used unless confirmed in writing. Company: none yet; a parent company may hold the account later.
